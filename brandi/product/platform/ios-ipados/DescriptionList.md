# DescriptionList on iOS and iPadOS

Label and value pairs on iOS are rows of a list, in two columns or stacked, and they stack by themselves at large text sizes.

| Field | Spec |
|---|---|
| Native control | None named in the registry. The closest pattern is a list whose rows pair a label with a value [APL-14]. |
| Target and spacing | Nothing here is pressed, so no hit area applies. Any control inside meets the 44 × 44 pt default and the 28 × 28 pt minimum [APL-1]. |
| Type | SF Pro through a text style, so it follows Dynamic Type [APL-3]. At large sizes, stack the value under the label [APL-3]. |
| Colour and theme | Labels take `secondaryLabel` and values `label` [APL-4]. Every custom colour needs light and dark variants, each with an increased-contrast option [APL-4]. |
| States | None. Each pair is static text, `isStaticText` or `.staticText` [APL-23] [APL-29]. |
| Motion | It has no motion of its own. Anything that animates near it follows Reduce Motion [APL-1] [APL-24]. |
| Accessibility API | VoiceOver reads each label with its value, grouped [APL-19]. |
| Navigation placement | A record's details, in the content or the detail column of a split view [APL-10]. |
| Keyboard, pointer, trackpad | Not a focus target. iPadOS keyboard focus covers content elements such as list items, text fields and search fields, and Full Keyboard Access covers controls [APL-15] [APL-16]. |
| Haptics | None specified for description lists. Apple names system haptics for toggles, sliders and pickers, and feedback generators for notification, impact and selection [APL-18]. |
| Brand may change | `columns` or `stacked`. A missing value says "Not set", never blank. The product's subtle label maps to Apple's secondary label colour [APL-4]. |
| Platform owns | Dynamic Type, which triggers stacking [APL-3]. |
| Not confirmed | A native label and value row style: no registry page names one. |
