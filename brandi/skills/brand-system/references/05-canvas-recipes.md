# 05. Canvas recipes

How to author `.dc.html` artboards for the `/design` canvas without hitting the traps.

Read this before writing an artboard by hand. The specification sheets (palette, typography,
components, tokens) are generated by `brandi sheets` and must not be hand-edited: they are correct
by construction and regenerating overwrites anything you change. Everything else on the canvas,
the direction sketches and the proof artboards, you write.

## The format in ninety seconds

One file, one artboard, one frame on the canvas.

```html
<!doctype html>
<html>
<head>
  <meta charset="utf-8">
  <script src="./support.js"></script>
</head>
<body>
<x-dc>
<helmet>
  <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Bitter:wght@400;700&display=swap">
  <style>
    * { box-sizing: border-box; }
    body { margin: 0; }
    a { color: #1F6F4A; }
    a:hover { color: #0F3A26; }
  </style>
</helmet>
<div style="padding: 64px; display: flex; flex-direction: column; gap: 24px;">
  <h1 style="margin: 0; font-family: 'Bitter', Georgia, serif; font-size: 64px;">The good kind of wet dog</h1>
</div>
</x-dc>
</body>
</html>
```

That is a complete, valid artboard. A static one needs no `<script data-dc-script>` block at all.

### The lines that must be exact

- `<script src="./support.js"></script>` in the head, character for character. The editor swaps it
  for the inline runtime. Removing it, inlining it, or adding an attribute breaks the artboard.
- `<x-dc>` wraps the content. `<helmet>` holds the stylesheet links and the `<style>` block.
- The filename is `PascalCase.dc.html` and the stem is the artboard's identity. `Main.dc.html` is
  the artboard a focused open lands on. The seeder WARNS rather than refuses when there is no Main,
  and treats the first artboard as the entry (verified against helper 2.1.251), so a Main-less seed
  works. Name one Main anyway: the entry artboard should be a decision, not alphabetical order.

## Ten silent failures

Every one of these renders without an error. That is why `brandi validate` exists: run it before
every publish.

1. **An expression inside a hole.** `{{ a + b }}`, `{{ !x }}`, `{{ fn() }}` render as literal text.
   Holes are dotted lookups only. Compute in `renderVals()` and bind the result.
2. **A ternary around a hole.** `style="color: {{x}} ? 'a' : 'b'"` renders as invalid CSS and is
   dropped. Precompute the branch.
3. **A single-quoted image src.** `<img src='logo.png'>` never resolves. Double quotes only, and the
   filename must match the files key exactly.
4. **A `data:` prefix on a stored image.** The runtime adds the wrapper itself, so a stored data URI
   double-wraps into a broken image. Store bare base64.
5. **Any external URL.** The canvas has no network egress. A CDN script, a remote image, a fetch, a
   stylesheet from anywhere except `fonts.googleapis.com`, all fail silently. Inline everything.
6. **A double-quoted `data-props` attribute.** It must be single-quoted, and inside it `&` is
   `&amp;` and a literal apostrophe is `&#39;`. Raw UTF-8 is fine as it is.
7. **An empty `<script data-dc-script>`.** This errors. Omit the block entirely for a static artboard.
8. **`<br>` inside editable text.** A `{{hole}}` bound to a text prop renders as a text node, so HTML
   in the value is escaped. For multiple lines, put `\n` in the value and `white-space: pre-line` on
   the element, or split into separate elements.
9. **A frame smaller than its content.** `w` and `h` in `canvas.json` set the frame; they neither
   scale nor crop. A 1123px-tall root inside a 900px frame clips. Surplus frame just paints the
   artboard's background, so size generously and always set a background.
10. **Siblings spaced with margins.** Use `display: flex` or `grid` with `gap`. Gap survives the
    canvas editor's drag-reorder, delete and duplicate; whitespace text nodes and per-element margins
    do not.

## Frames

## canvas.json

```json
{
  "artboards": [
    { "file": "Main.dc.html", "x": 0, "y": 0, "w": 1440, "h": 1600, "page": "work" },
    { "file": "Mobile.dc.html", "x": 1560, "y": 0, "w": 390, "h": 844, "page": "work" },
    { "file": "Print.dc.html", "x": 2070, "y": 0, "w": 794, "h": 1123, "page": "work", "print": "fixed" }
  ],
  "annotations": [
    { "id": "why-green", "x": 0, "y": -160, "w": 420, "text": "Green is inherited from the shopfront.\nSee decision d1." }
  ],
  "pages": [
    { "id": "work", "name": "Design" },
    { "id": "spec", "name": "Specification" }
  ],
  "launch": { "view": "canvas", "page": "work" }
}
```

- Leave at least 80px between frames in a row and 120px between rows. The name strip and tweak chips
  sit above each frame and will collide otherwise. `$A validate` checks both: a true overlap is an
  error, and a gap under those minimums is a warning.
- Every `.dc.html` in the folder becomes an artboard whether you list it or not. An unlisted one gets
  an arbitrary slot, so list them all.
- Annotation `text` is one plain string with `\n` for newlines, never an array. Ids are unique,
  1 to 40 characters of letters, digits, hyphen and underscore.
- `launch` is either `{"view": "canvas"}` (optionally with `page`) or
  `{"view": "focused", "file": "..."}`. Set it to the page you just worked on.
- Print pieces are a series of single-page artboards on ONE page, with `"print": "fixed"`. A flowing
  document (a memo, a report) is one artboard with `"print": "flow"`, which paginates on PDF export.

## Recipe: a direction sketch

Three of these, from three different families in `03-design-schools.md`. Low fidelity on purpose.
The job is to make a choice possible, not to finish anything.

Frame 900 x 1100. Each one carries, in this order:

1. The direction's name and a one-line pitch, in the direction's own display face.
2. A hero composition, roughly blocked. Real headline copy in the brand voice, no lorem.
3. The palette as a strip, with hex values.
4. The type pairing, one line each, at real display and body sizes.
5. The signature move, drawn, with a caption naming it.
6. The honest tradeoff, one sentence, in small type at the bottom.

Give every direction the same six parts in the same order, so they can actually be compared. Make
each one a genuinely different bet: a set where only your favourite gets a case made for it is a
rigged vote.

Open the file with the mini-system comment so the choices stay legible:

```html
<!--
  Direction B: Craft heritage
  Type: Bitter 72/44 display, Karla 17 body, one family each
  Colour: #1F6F4A ground, #F4EFE6 paper, #D4823A accent used once
  Grid: single column, 64px margins, rules between sections
  Signature: the shake silhouette, cropped past the frame edge
-->
```

Keep direction names stable across turns. Once an artboard is "Direction B, craft heritage" it keeps
that identity, even if the order changes.

## Recipe: the proof artboards

These are the stress test. The system either survives real work or it does not, and finding out here
is much cheaper than finding out in production.

**`Main.dc.html`, the website.** Marketing-page anatomy: a hero that states the offer in one
sentence with one call to action; proof a visitor can actually trust (drawn from the client's own
material, or visibly marked as a placeholder); sections that answer a real doubt rather than listing
features. One primary action, repeated down the page, not three competing buttons. Check it at phone
width and fix what breaks before you show it.

**`Product.dc.html`, a dense screen.** This is where systems fail, so make it hard: a data table with
tabular numerals, a form with a field in every state, a filter bar, a toast, an empty state and an
error. If the type scale has no step that works in a table row, better to find out now.

**`Mobile.dc.html`.** 390 x 844. Targets at least 44px. No fake iOS status bar and no fake keyboard:
on a real phone the real ones render on top and a painted one looks doubled up.

**`Deck.dc.html`.** 1920 x 1080. One slide, done properly. Body type at 24px or larger. One or two
background colours across a deck, so a different background means something.

**`Social.dc.html`.** 1080 x 1080. It has to read at thumbnail size. Squint at it: if the hierarchy
survives, it works.

**`Print.dc.html`.** A4 at 794 x 1123. Body type at 12pt (16px) or larger. Check it in greyscale,
because someone will print it that way. No hairlines under 1px and no huge dark flood fills.

## Typefaces on the canvas

Google Fonts is the only host the canvas can reach. A `<link rel="stylesheet">` to
`https://fonts.googleapis.com/...` inside `<helmet>` works; every other host is blocked silently.
Anything else has to be a `@font-face` with a `data:` URI inside the artboard.

Always give a fallback stack with close metrics: PNG and PDF export cannot embed a web font, so
exported text renders in the fallback. Size headlines with about ten percent of slack so a
substituted face does not overflow.

Banned outright, whatever the brief: Inter, Roboto, Arial, Helvetica Neue, Fraunces, Poppins,
Montserrat, Open Sans, Lato, Nunito, Raleway. `04-anti-slop.md` names replacements.

## Icons

Drawn, never typed. Inline SVG on a 16, 20 or 24 pixel grid, one consistent stroke weight, one
consistent cap and join. Emoji render differently on every platform and read as a tell immediately.

```html
<svg width="20" height="20" viewBox="0 0 24 24" fill="none" stroke="currentColor"
     stroke-width="2" stroke-linecap="round" stroke-linejoin="round" aria-hidden="true">
  <path d="M20 6 9 17l-5-5"/>
</svg>
```

## Images

Store as a bare base64 files entry under the basename, reference by filename with double quotes.
Keep each under about 70 KB: the whole document republishes on every save, there is a 16 MB cap, and
the editor silently drops anything over 2 MB.

```bash
sips -Z 1200 photo.jpg --out brand/canvas/photo.jpg     # macOS
magick in.png -resize 1200x brand/canvas/photo.png      # ImageMagick
```

`brandi canvas` passes every image in the folder to the seeder automatically. Two images sharing a
basename are refused, so name them distinctly.

## Interactivity

Only when the brief asks for a prototype. Working controls need a logic block:

```html
<script data-dc-script data-props='{"accent":{"editor":"color","default":"#1F6F4A"}}'>
class Component extends DCLogic {
  renderVals() {
    const options = ['Wash', 'Wash and dry', 'Full groom'];
    return {
      accent: this.props.accent ?? '#1F6F4A',
      options: options.map((label, i) => ({
        label,
        selected: this.state?.picked === i,
        pick: () => this.setState({ picked: i }),
      })),
    };
  }
}
</script>
```

Classic script only: no `import`, no `export`, no TypeScript, and the class must be
`class Component extends DCLogic`. Events use JSX camelCase as whole-value attributes,
`onClick="{{ item.pick }}"`. Always set `hint-placeholder-count` on `<sc-for>` and
`hint-placeholder-val` on `<sc-if>` so something renders while values stream in.

Mark the artboard `"is_interactive": true` in `canvas.json`.

**Tweaks are levers, not copy.** A `data-props` entry with an editor becomes a chip above the
artboard. Declare few and deliberate ones: a theme toggle, a density switch, one accent colour that
cuts across the whole design. Never make a tweak for body copy, and never for a colour used in one
place: a viewer retypes copy in place and restyles a single element in the properties panel.

## Look at it before you publish

The validator is structural. It cannot tell you that a layout is bad, only that it is broken, and
the two mistakes most likely to reach a client are neither.

```bash
node <brandi>/scripts/preview.mjs brand/canvas/Deck.dc.html --out /tmp/p --width 1920 --height 1080
node <brandi>/scripts/preview.mjs --dir brand/canvas --out /tmp/p   # all of them
```

Two traps worth knowing, both found by looking rather than by checking:

- **A measure on the column, not the child.** `max-width: 24ch` on a flex column holding a 96px
  headline and a 30px paragraph starves the paragraph: 24ch of the display face is roughly four
  times 24ch of the body face, so the body copy wraps at about fourteen characters and everything
  below it is pushed out of the frame. Put the measure on each child.
- **Cropping a mark on two edges.** A signature element cropped past one edge reads as deliberate.
  Cropped past two, with the part that carries its identity outside the frame, it reads as a smudge.
  Decide which part must stay in frame before choosing the crop.

## Before you publish

`$A` is the command resolved at the start of the session, per the skill: `brandi` when the plugin is
installed, and `node <skill base directory>/../../scripts/brandi.mjs` when working from a clone. It
is never a bare relative path: the working directory is the user's project, not the plugin.

```bash
$A validate --dir brand/canvas
```

Errors mean it will not render correctly. Warnings mean it will render, and look generic. Fix the
errors, and have a reason for any warning you leave.

Then seed and publish:

```bash
$A canvas --dir brand/canvas --title "Muddy Paws brand" --out muddy-paws-brand.html
```

Publish the file it names with the `Artifact` tool: `contract: "0.1.31"`, a one-line description, and
a favicon of one or two emoji that stays the same for the life of the canvas.

To change anything afterwards, edit the working files in `brand/canvas/` and re-run `brandi canvas`.
It always seeds a fresh copy. Never edit the seeded output file.
